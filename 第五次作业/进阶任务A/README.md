# 进阶任务 A：多线程视觉检测与目标跟踪

本目录实现 `rm_vision_sim`，不依赖 ROS/ROS 2。程序用四个工作线程完成视频读取、蓝色目标检测、运动跟踪和结果写出，模块之间通过有界线程安全队列传递数据。

## 目录结构

```text
.
├── config/vision.conf
├── data/test_video.avi
├── data/ground_truth_public.csv
├── include/
├── src/
├── tools/check_result.py
├── CMakeLists.txt
└── test.sh
```

## 编译运行

Ubuntu 22.04 环境安装依赖：

```bash
sudo apt update
sudo apt install -y build-essential cmake libopencv-dev python3
```

在本目录执行：

```bash
cmake -S . -B build
cmake --build build --parallel
./build/rm_vision_sim config/vision.conf
```

程序将生成：

- `output/result.csv`：每帧的检测、预测、跟踪位置和速度；
- `output/result.avi`：绿色检测圆、红色有效跟踪十字和橙色纯预测十字。

公开测试可一键运行：

```bash
bash test.sh
```

测试会检查 60 帧完整输出、可见帧检测率、检测中心误差、跟踪误差、25～28 帧遮挡预测和可视化视频。

## 实现说明

### FrameSource

读取配置中的视频文件，使用视频自身 FPS 计算微秒时间戳，并用序号保证帧 ID 连续。时间戳经过单调性保护，即使输入 FPS 精度不足也不会倒退。读完视频后关闭 `frame_queue`。

### ColorDetector

每帧先转换到 HSV，再用配置中的六个阈值分割蓝色区域。3×3 椭圆结构元素依次执行开运算和闭运算，随后提取外轮廓，按面积范围过滤候选，并用面积和圆度选择最可靠的目标。没有合法轮廓时输出 `detected=0`。

### TargetTracker

采用 alpha-beta 常速度模型，状态为 `x, y, vx, vy`。每帧先按实际时间间隔预测位置，再用检测结果修正位置和速度。检测点距离预测位置超过 `max_match_distance` 时视为离群点并拒绝更新；连续漏检不超过 `max_missed_frames` 时继续输出预测，超过阈值后跟踪失效，目标重新出现时重新初始化。

### ResultWriter

CSV 首行固定为：

```text
frame_id,timestamp_us,detected,predicted,measure_x,measure_y,track_x,track_y,vx,vy
```

有效浮点数保留三位小数，无效位置写为 `nan`。视频写出不会因单帧漏检中断：检测位置绘制绿色圆，有效跟踪位置绘制红色十字，纯预测位置绘制橙色十字。

### 队列与退出

三个队列均有固定容量。生产者在队列满时等待，消费者在队列空时等待，`close()` 会唤醒所有等待线程。任意线程异常都会记录首个异常并关闭所有队列；主线程最后统一 `join`，保证没有后台线程遗留。

## 算法分析题

1. **HSV 阈值在亮度剧烈变化时为什么可能失效？** 亮度变化会改变 V，并可能连带影响 S；固定阈值会把原目标过滤掉，或把背景高光纳入掩膜。应合理设置 V/S 范围，必要时做亮度归一化或自适应阈值。
2. **形态学开运算和闭运算分别解决什么问题？** 开运算先腐蚀后膨胀，用于去除小噪声和孤立点；闭运算先膨胀后腐蚀，用于填补目标内部小孔洞、连接相邻断裂区域。
3. **如何从多个蓝色轮廓中选择真正目标？** 先按面积范围过滤，再综合轮廓面积和圆度评分，选择最可靠候选；不能使用视频中的固定坐标。
4. **为什么直接使用每帧检测中心会产生抖动？** 检测受像素量化、边缘噪声、遮挡和光照影响，中心点会在真实位置附近波动；直接输出没有利用连续运动信息。
5. **Kalman Filter 中预测和更新分别完成什么任务？** 预测根据上一时刻状态和运动模型推算当前状态；更新用当前观测与预测的差异修正状态，并按噪声可信度平衡模型和观测。
6. **目标短暂消失时为什么还能输出预测位置？** 跟踪器保留上一时刻的位置和速度，在允许的漏检帧数内继续做状态预测；这样短遮挡不会使轨迹中断，超过阈值后才标记无效。
